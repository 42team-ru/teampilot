# Рефакторинг processor в llm-worker

## Цель
Отрефакторить `llm-worker/processor.py` — улучшить структуру/читаемость/тестируемость,
без изменения внешнего поведения (контракты Kafka-топиков и LLM-цепочек сохраняются).

## Контекст
- `llm-worker/processor.py` — основной обработчик: читает батчи сообщений, гоняет LLM-цепочки
  (`llm/chains.py`), пушит события создания/смены статуса задач.
- Рядом: `sync_processor.py`, `api.py`, `llm/` (chains, voice_agent, prompts, parser, transcript).

## Что нужно (уточнить при брейншторме)
- Разбить «божественные» функции на узкие единицы (парсинг → решение → публикация).
- Вынести побочки (Kafka publish, backend-вызовы) за чистую логику решений → тестируемость.
- Единая обработка ошибок/ретраев; убрать дублирование с `sync_processor.py`, если есть.
- Покрыть ключевые ветки юнит-тестами (`tests/`).

## Критерий
Поведение идентично (те же топики/события), код чище, есть тесты на основную логику.

## Зависимость
Может пересекаться с задачей переноса call-агента — согласовать порядок (сначала перенос,
потом рефактор оставшегося worker-пайплайна, либо наоборот).

## Вне скоупа
Изменение бизнес-логики извлечения задач, смена LLM-провайдера.
