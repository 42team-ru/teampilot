# Перенос call-агента из llm-worker в telemost-bot

## Цель
Всё, что связано с LLM-агентом «Пилот» и его дёрганьем **во время звонка** Telemost,
перенести из `llm-worker` в `telemost-bot`, чтобы обработка голоса не блокировалась
отправкой аудио-чанков и прочими фоновыми задачами бота.

## Контекст (как сейчас)
- `telemost-bot/voice_qa.py` ловит фразу → HTTP `POST llm-worker /voice/answer` → llm-worker
  (`llm/voice_agent.py`) делает tool-calling по доске (backend) и TTS, возвращает аудио.
- Параллельно бот шлёт аудио встречи чанками (`chunk_sender.py`) в Kafka/MinIO.
- Проблема: голосовой Q&A и чанк-отправка мешают друг другу / блокируются.

## Что нужно
1. Перенести логику агента (`voice_agent.py`, вызовы backend-инструментов, TTS-триггер)
   из `llm-worker` в `telemost-bot` (агент исполняется локально в боте, без HTTP-хопа в worker).
2. Сделать обработку голоса **неблокирующей** относительно чанк-отправки: разнести по
   независимым asyncio-таскам / очередям, чтобы STT+агент+TTS не тормозили чанкование и наоборот.
3. Сохранить текущий контракт ответа (аудио в звонок) и доступ к backend-инструментам
   (counts/list/search/create/status/assign — учесть задачу voice-actions).

## Открытые вопросы для брейншторма
- llm-worker остаётся как general-LLM (батчи сообщений) — переносим только call-path?
- Где живут промпты/ключи LLM после переноса (общий модуль vs дубль в боте)?
- TTS (`infra/tts.py`) тоже переезжает в бота?

## Вне скоупа
Рефактор processor.py (отдельная задача), оффлайн wake word.
